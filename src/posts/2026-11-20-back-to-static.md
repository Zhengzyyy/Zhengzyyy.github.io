上一次认真写博客，还是用一个现成的主题。改配色要翻三份配置文件，加一个页面要理解插件的生命周期，升级依赖之后构建挂了，而我不知道为什么。写作本来已经够难了，不该再和工具搏斗。

所以这次我做了个决定：把博客搬回自己手里。

## 为什么离开 Jekyll

Jekyll 没有做错什么。它仍然是静态博客最稳妥的选择之一，只是它默认了一套我不再需要的抽象。主题、布局、集合、插件，这些概念在文章多起来之后很有用，但对一个只想写点东西的人来说，它们更像是一层需要维护的中间人。

更直接的原因是环境。我的机器上没有 Ruby，每次换电脑都要重新折腾一遍版本管理器。而 Node 本来就在，构建一个静态站点需要的所有东西——模板字符串、文件读写、Markdown 解析——它都有。

于是我把整个站点的构建过程压缩成了一个入口：

```bash
npm install
npm run build     # 输出到 dist/
npm run dev       # 本地预览，改文件自动重建
```

没有 watch 插件，没有热更新框架，没有配置文件继承链。改一行 CSS，刷新页面就能看到结果。

## 一套足够小的构建流程

构建脚本只做四件事：

1. 读取 `src/posts/` 下的 Markdown，解析 frontmatter；
2. 把正文渲染成 HTML，同时收集标题生成目录；
3. 按标签和分类聚合文章，生成归档页与索引页；
4. 把模板、样式和脚本拼成最终的 `dist/`。

目录结构也尽量扁平：

| 路径 | 作用 |
| --- | --- |
| `src/posts/` | 文章，一天最多改一次 |
| `src/pages/` | 关于页这类独立页面 |
| `src/assets/` | 样式、脚本、图标 |
| `scripts/` | 构建和预览脚本 |
| `dist/` | 构建产物，不提交到 Git |

表格里最值得说的是最后一行。以前我会把生成结果也提交上去，导致每次改一个错别字，diff 里都是一大片被压缩过的 HTML。现在 `dist/` 完全由 CI 生成，仓库里只剩下源文件。

## 内容仍然只是 Markdown

我特意保留了写作的手感：打开一个 `.md` 文件，写标题、日期、分类，然后开始写正文。代码块、引用、列表、图片，都是最普通的 Markdown 语法。

```md
---
title: "一篇文章的标题"
date: "2026-11-20"
category: "工程"
tags: ["静态站点", "写作"]
summary: "一句话说清楚这篇文章在讲什么。"
---

正文从这里开始。
```

唯一的约定是日期要写成带引号的 `YYYY-MM-DD`。不加引号的话，YAML 会把它解析成时间对象，时区一折腾，文章就可能跑到前一天去。这种小坑不值得第二次踩。

## 把注意力还给写作

搬家完成之后，我发现自己打开编辑器的次数变多了。原因很简单：从“想写”到“开始写”之间，只剩一个空文件。

工具应该退到背景里。它最好足够小，小到我能完整地理解它；又足够稳，稳到我几个月不碰它也不会坏。现在的这套东西大概就是这样：没有框架，没有魔法，出问题的时候，我知道该去哪个文件里找。

这就够了。
